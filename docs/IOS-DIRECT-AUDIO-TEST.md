# 음원만 직접 연결 · BitChord iOS 테스트

[테스트 IPA 다운로드](../artifacts/BitChord-Test-1.0.2.ipa) · 빌드 47

앱 이름은 **BitChord Test**, 번들 ID는 **com.music.bitchord.test**입니다. App Group과 Keychain 서비스 이름은 정식 앱과 같은 원래 값으로 유지하며 별도 저장소로 옮기거나 기존 데이터를 지우지 않습니다. 실제 로그인·설정 승계 여부는 설치할 때의 재서명 권한과 도구 설정에 따라 달라질 수 있습니다. 전체 로그 기록은 테스트판에서 기본 켜짐이며, 사용자가 끄면 그 선택을 유지합니다.

1. 앱 내부 WireGuard를 켜고 기존처럼 미국 또는 일본 프로필로 연결합니다. 한국 회선을 비교할 때는 기기 전체 VPN을 끕니다.
2. **설정 → 계정 및 연동 → 프록시 → 음원만 직접 연결 (테스트)**를 끈 채 앱을 재시작합니다. **설정 → 진단 → 전체 로그 기록**에서 기록을 켜고 재생 캐시를 지웁니다.
3. YouTube 곡 몇 개를 켜고 첫 재생, 중간 탐색, 다음 곡으로 넘어갈 때의 대기를 봅니다. 애드온 음원과 섞이지 않도록 두 번 모두 **빠른 재생**으로 비교하는 것을 권장합니다.
4. **음원만 직접 연결 (테스트)**를 켜고 앱을 재시작합니다. 같은 Wi-Fi와 WireGuard 프로필에서 재생 캐시를 지우고 같은 곡들을 비교합니다. 테스트 조건은 전체 로그와 함께 기록하면 됩니다.

로그에서 `direct probe passed`는 음원 주소 검사 통과, `direct media bytes received`는 실제 음원 데이터 수신, `proxy fallback`은 WireGuard 재시도를 뜻합니다. 완전히 캐시된 곡은 네트워크 연결을 사용하지 않습니다.

스위치는 기본 꺼짐입니다. 켜면 YouTube의 HTTPS 음원 데이터 요청에 한해 음원 서버가 기기의 연결 IP를 볼 수 있습니다. 로그인, 재생 주소 발급, 애드온과 다운로드의 경로는 기존과 같습니다.

## 2026-11-17 실기기 로그 결과

빌드 45에서 직접 연결 검사 13회 중 HTTP 403이 10회, HTTP 302가 2회, 시간 초과가 1회였습니다. 직접 수신 성공은 0회이고, 로그에 기록된 음원 Range 요청 93회는 모두 프록시를 사용했습니다.

직접 배달을 통한 속도 개선은 아직 확인되지 않았습니다. 403의 정확한 사유는 서버 응답만으로 확정할 수 없지만, 주소 발급 시점과 수신 시점의 IP가 달라 거부되는 경우와 맞는 패턴입니다. 302는 이 테스트에서 리다이렉트를 허용하지 않아 최종 성공 여부가 미확인입니다. 이 실험의 직접 연결 검사는 실패 시 추가 대기를 발생시킵니다.


## 클라이언트 비교 · 빌드 47

1. 앱 내부 WireGuard는 켜고 **음원만 직접 연결 (테스트)**는 끕니다.
2. 프록시 화면의 **YouTube 클라이언트 비교 (테스트)**를 켠 뒤 앱을 완전히 종료하고 다시 엽니다.
3. **빠른 재생**으로 YouTube 곡 하나를 골라 2~3분 정도 넘기거나 정지하지 않고 듣습니다. 애드온 곡과 완전히 캐시된 곡은 비교가 시작되지 않을 수 있으므로 필요하면 재생 캐시를 먼저 지웁니다.
4. 전체 로그를 공유합니다. `ClientCompare`가 클라이언트별 결과이며 `comparison finished`까지 있으면 한 곡 검사가 끝난 것입니다. 실행당 한 곡만 검사합니다.

비교 대상은 visionOS, iOS, Android VR, 임베디드 웹, YouTube Music 웹, TV, 모바일 웹입니다. 재생 20초 뒤 순차적으로 검사하며, 현재 곡을 바꾸거나 정지하면 다음 검사를 중단합니다. 주소를 발급받지 못한 클라이언트도 결과를 기록합니다.

`proxy=206 direct=206 directTail=206`이면 같은 주소가 두 경로에서 읽혔고 직접 연결로 끝부분도 읽힌 것입니다. `proxy=206 direct=HTTP 403`이면 프록시에서는 허용되고 직접 연결에서는 거부된 것입니다. 성공한 후보를 현재 재생에 자동 적용하지 않으며 파일 전체 수신과 실제 재생·탐색은 이후 검증이 필요합니다. 비교 요청은 별도 짧은 Range를 사용하므로 네트워크와 배터리를 추가로 사용합니다. 주소·서명·쿠키는 요약 로그에 넣지 않습니다.

리다이렉트는 HTTPS Google 음원 서버로만 최대 3회 허용하고, 그 외 서버나 인증정보가 들어간 주소로는 따라가지 않습니다. 이 리다이렉트 검사는 진단 전용이며 기존 음원 직접 연결 스위치의 동작을 바꾸지 않습니다.
